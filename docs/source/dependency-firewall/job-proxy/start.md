Start the job-level proxy and print shell exports to route the job through it.

## Synopsis

Start the job-level Dependency Firewall proxy as a background process and print `export` lines that route the current shell through it. Evaluate the output so the exports apply to the rest of the job.

If the proxy cannot start, the command prints `false`, so the `eval` fails and a CI/CD job (which runs with `set -e`) stops instead of running without the firewall.

The proxy stores the project's unreachable fallback in `.gitlab/df/policy-summary.json`. Cache that file between jobs with `cache:paths`, so a job that starts while GitLab is unreachable can still apply it. The stored copy is used only when Git confirms it isn't committed, so the job needs `git` and a checkout of the repository. A job with `GIT_STRATEGY: none` gets no fallback.

```plaintext
glab dependency-firewall job-proxy start [flags]
```

## Examples

```console
# In before_script: route the rest of the CI/CD job through the proxy
eval "$(glab dependency-firewall job-proxy start)"

# As the last command in script: fail the job if a package was blocked
glab dependency-firewall ci-summary

```

## Environment variables

```plaintext
GLAB_DF_JOB_PROXY_STATE_DIR: directory for the proxy's runtime state (address, pid, CA). Set it to pin a known location; otherwise start creates a fresh per-user directory and exports this variable so `job-proxy stop` finds the same proxy.
```
